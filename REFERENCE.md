## How an FSOT build is made

The builds on the account follow one shape.

1. The law stays in the hub. [FSOT-2.1-Lean](https://github.com/dappalumbo91/FSOT-2.1-Lean) holds the proofs. [FSOT-2.1-Cpp](https://github.com/dappalumbo91/FSOT-2.1-Cpp) is the current numerical port and is golden-checked against the same Python engine. An application loads that law. It does not paste a private copy and it does not add a coefficient so a demo lands closer.
2. The application names one object and one pin. A kernel, a translator, a compressor, and a circuit are different objects. Their scores do not move each other.
3. The host language is the vessel for that object. Rust `no_std` boots the kernel. Zig is the bare-metal translator and the neuron authority. C writes the compressor's bytes. Python is the pass language and the data factory. Ada is a shipping binary for the translator. The vessel is allowed to change. The scored object is not.
4. A reference may be studied and is not imported. Reality OS reads Linux for the list of pathways a kernel has to cover, and the kernel source is its own.
5. A miss stays a miss. The floor is written before the run. A later listen does not move the floor.

The file rate in the compressor is the leftover conditional entropy, the part the library does not already contain. The pump fraction is stored in the header and is not the compression ratio. The same discipline applies here. Three masses stay separate:

- **Program text.** The lines a person writes for the behavior.
- **Project text.** Manifests, build files, and lockfiles the tool requires before that text will run.
- **Vessel.** The binary that ships, or the interpreter a source file assumes is already installed.

A small Python file on a large interpreter is a small program text and a large shared vessel. A Rust binary packs more of the vessel into the file that ships. Those are different objects. Beating one and losing the other is a miss on the object that was named.

Two compressor results transfer directly.

- Storing a metric in place of the archive keeps the metric and loses the bytes. A shorter syntax that does not rebuild the same program is that kind of miss.
- An object whose entropy is already above the size bar cannot be saved by a cleverer packing of the same symbols. Skrillex and VNV stayed over Opus because the kept spectrum was already bigger than the bar. If a program's sense is already the short form, a new language cannot shrink it. The mass has to be somewhere else: repeated sense, a restated contract, or a vessel that was counted as if it were the program.

## What "make a language" means here

Protofluid already maps natural-language form onto one sense and back onto another form. Sensepin asks the same question of programs. The name is that sense, pinned to a law.

The sense is the behavior named in a probe contract. The forms are Python, C, Rust, Zig, Go, and whatever host the probe adds later. Sensepin carries the residual: the part a shared gauge cannot rebuild. It lowers to C, so the work is the notation and the gauge.

The gauge is earned from probes. It is the set of shapes that showed up more than once, with the same behavior, across hosts. Probe 00 put file, line, and integer handling in every host. Sum and bounds reuse those gauges on a different residual. Probe 01 put a name and an integer on one line. The five hosts grew by 695 to 969 bytes. Sensepin v0 cannot cut a line into those two fields, and it cannot divide, so that probe has no Sensepin residual.

The contract is [fold/SPEC.md](fold/SPEC.md). Source files use `.sensepin`. The working tree keeps the directory `fold/` and the `fold_` prefix.
